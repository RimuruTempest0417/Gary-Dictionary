# v0.14.1 — 修：生字卡的操作按鈕在真機上被裁掉（使用者於真機實測抓到）

- 發佈日期：2026-10-11
- 線上：https://gary-dictionary.vercel.app
- 上一版：v0.14.0（F-2 加到主畫面）

## 症狀（使用者在自己的 iPhone 上抓到）

在生字表頁、**A+ 字級**（或中文介面的「錄音／上傳」）時，生字卡最下面那一列操作按鈕
（`✏️ 編輯 ／ 🗑 刪除 ／ 🎙 錄音／上傳`）**最右邊那顆會凸出卡片右緣、文字被裁掉**。

## 根因

`public/css/app.css` 手機版（≤640px）的規則：

```css
.vocab-actions { flex-direction: row; width: 100%; }      /* 沒有 flex-wrap */
.vocab-actions .btn { flex: 1 1 auto; }                   /* 沒有 min-width: 0 / max-width */
```

`flex: 1 1 auto` 只代表「可以縮」，但按鈕的最小寬度是它的**文字寬度**（`white-space: nowrap`），
所以三顆按鈕的總寬超過卡片時，第 3 顆只能溢出（`flex-wrap` 不在就沒地方去）。

## 修法（兩層）

1. **`.vocab-actions` 加 `flex-wrap: wrap`**：塞不下就換行（真正的解法）。
2. **`.btn` 加 `max-width: 100%`（全站）**：任何按鈕都不可以比容器寬 —— 這是防止同類問題
   出現在別處的通用防線（單點修好一個地方沒用）。

## 守門（這次是「先確認守門抓得到」才發版）

`tests/browser/users-check.js` 新增矩陣：**中／英 × A／A+ × 320/375/402px**，
在生字表頁檢查

- 所有控制項都在畫面內（`getBoundingClientRect()` 不超出視窗）
- ★ **沒有任何按鈕的文字被裁掉**（`scrollWidth > clientWidth + 1`）
- 整頁不橫向溢出

★ 為什麼要加「文字被裁」這一條：**只量「框有沒有凸出」抓不到這個 bug**（`max-width` 會讓框乖乖在裡面，
但字已經被切掉）。實測把 `flex-wrap` 改回 `nowrap` 時，守門會紅並指出
`6 個被裁：["✏️ 編輯","🗑 刪除","🎙 錄音 / 上傳"]` —— 確認它真的敏感。

★ 同時發現一件重要的事：**同樣的版面在 Chrome 要到 320px 才溢出，使用者的 iPhone（約 390px）就中了**
→ **iOS Safari 的字寬比桌面 Chrome 寬**。這就是為什麼 v0.13.2 在桌機量不到「Sign out 凸出」，
而使用者在真機看得到。**教訓：手機版面不能只靠桌面 Chrome 的模擬寬度驗收，要在真機（或 iOS 模擬器）看一次。**
